# 入局 · 知乎盐言故事互动叙事游乐场
## 产品说明计划书

> **赛道**：跨次元游乐场 —— AI 游戏与互动叙事
> **体验地址**：https://storydive-10wtw01.org （国内直连，游客免登录即玩）
> **一句话介绍**：把知乎盐言故事变成可以"玩"的互动叙事游乐场——读者走进名场面与角色对戏、推演分叉、改写剧情，再把自己长出的故事送进社区，与所有人接力、对赌、共演。

---

## 一、创作思路：从"读完即止"到"入局即玩"

### 我们观察到的三个问题

**1. 盐选故事的体验是单向的。**
知乎盐言故事积累了大量高质量短篇（校园、言情、悬疑、历史、脑洞……），读者的典型路径是：点开 → 追更 → 读完 → 关闭。情绪浓度在"读完那一秒"达到峰值，却没有任何出口——想跟主角说句话、想改一个结局、想看看"如果当初"，都无处安放。

**2. 社区的共创冲动缺少"叙事容器"。**
知乎天然有观点对抗（红蓝视角、高赞反驳）和续写接力的传统，但文字评论区的共创是碎片化的：盖楼会歪楼，续写会失散。社区缺一个**结构化的叙事容器**，让"接得下去、对得起来、留得下来"。

**3. 热榜议题与故事消费是两个世界。**
热榜是知乎每天最大的流量心智，但它以"议题"存在，缺少戏剧化的演绎入口。如果热榜上的"第一次当领导被下马威"能变成一局可以亲自玩的迷你剧呢？

### 我们的解法

把**盐选故事 IP** 作为内容底座，把**名场面**作为入口：读者不再是读者，而是"入局者"——走进故事的关键时刻，与 AI 驱动的角色实时对戏；每一个选择都长出一条支线；每一条支线都可以发布到公共工坊，被别人接力续写、点赞、开庭对赌；每天还有一局由知乎热榜话题现生成的"盐灵剧场"。

故事不再被"读完"，而是被"玩起来、长下去"。

## 二、产品详解：六个场景走完一圈

### 2.1 旧物书架 —— 29 部盐选故事的入口

首页是一座暗色调的「旧物书架」：每部作品不是一张封面卡，而是**一件故事旧物**——写满错题的卷子、一枚外戚印信、一把佛塔钥匙、一片垂落的人皮。"点亮一件旧物，入一个局"。支持按标题/作者搜索，脑洞、言情、悬疑、历史等 60+ 标签一筛即得。

![旧物书架](screenshots/01-shelf-home.png)

### 2.2 阅读 + 故事图谱 —— 先看懂，再入局

点开旧物即进入导读式正文（原创复述，尊重原作版权并署名来源），每章配场景插画。右上角随时展开**故事图谱**：人物关系网（星座式星图，节点可拖拽重排，连线标注"君臣""敌视""续命·结盟"）、情节时间线、入局点分支树——先用 30 秒建立空间感，再决定从哪里入局。

![故事图谱](screenshots/03-graph.png)

### 2.3 AI 三种玩法 —— 对戏、分叉、改写

每个入局点提供三种与 AI 实时交互的玩法：

- **对戏**：以"我"的身份与场景内角色实时对话。AI 以角色人设卡（性格/立场/说话方式）+ 已读剧情为上下文，角色"记得"你说过的话，敌视你的角色句句带刺，暗恋你的角色欲言又止。
- **分叉**：在关键选择处，AI 推演一条平行走向的完整剧情——"如果她没有接那通电话"。
- **改写**：给一个脑洞设定，AI 顺着原作文风续写改篇——"如果秦始皇收到了一份世界地图"。

此外还有**群像**（多位角色同场交锋）与**复盘**（对纪实类作品的选择进行推演反思）。

### 2.4 支线树 —— 你的每一次选择都被记住

每段对局自动存为一条**支线**：属于你个人的叙事树，支持从任意支线节点"继续往下玩"，长出子节点。这是读者自己的故事资产，也是后续所有社区玩法的原料。

### 2.5 二创工坊 —— 接力盖楼的公共内容池

支线可以"发布"进公共殿堂：别人可以在你的改写之后**接力盖楼**（形成一条链）、**点赞**（热度加权排序，新内容有 48 小时新鲜度加成）。这是知乎"回答接力"传统的游戏化重建。

![二创殿堂](screenshots/06-hall.png)

### 2.6 名场面法庭 —— 红蓝对赌的社区判决

系统从故事中现取一个两难名场面，由 AI 扮演红蓝两造交锋三回合，观众**投票定胜负**、可改投、实时票仓，结束后 AI 盐官依票数宣读判词，并生成可保存分享的**判决书海报**。把知乎的"观点对抗"文化装进了一个戏剧容器。

![名场面法庭](screenshots/05-court.png)

### 2.7 盐灵剧场 —— 热榜驱动的每日一局

调用知乎开放平台热榜 API，把当日热点话题喂给 AI，现生成一局"多结局微剧场"：你扮演话题中的当事人，三五个选择走出 good / bad / twist / open 四种结局。热榜一天一取、按日轮换选题，**天然日更**；接口不可用时自动降级到本地话题池，永不空场。

![盐灵剧场](screenshots/04-theater.png)

## 三、技术方案：一个 Worker，零台服务器

![技术架构](screenshots/08-architecture.png)

### 3.1 全栈跑在 Cloudflare 边缘

Next.js 16（App Router）+ React 19 构建的前端与服务端 API，经 OpenNext 适配为**单个 Cloudflare Worker**：SSR 渲染、8 组 API 路由、静态资源、签名会话全部同源承载，国内直连访问 1.5s 内打开。数据层使用 Cloudflare D1（SQLite），Drizzle ORM 管理 4 张表（用户、支线、法庭票仓、工坊接力链）。

### 3.2 AI 层：一个 OpenAI 兼容接口驱动七类能力

服务端统一通过 **OpenAI 兼容协议**（`api.openai-next.com/v1`，DeepSeek v4 flash）调用，一个 SDK 接口覆盖全部七类 AI 能力：对戏、群像、分叉、改写、复盘、法庭攻防与判词、剧场生成。每类能力有独立的 System Prompt 工程（人物设定卡 + 人物关系图谱 + 已读正文作为上下文锚点），流式输出，AI 不可用时全链路降级兜底（静态剧场、本地话题池），**Demo 永不空场**。

### 3.3 深度使用知乎开放平台（合规、官方、三能力）

- **热榜 API**（`content/hot_list`）：盐灵剧场的每日选题源。应用层做"一天一取"缓存 + 并发去重 + 按日确定性轮换，尊重接口额度。
- **OAuth 登录**（黑客松授权流程）：知乎账号一键登录，授权码换 token 全程在服务端完成。
- **用户数据 API**：以 Access Secret + X-OAuth-Token + 时间戳头代表用户读取资料，作为站内昵称与头像来源。
- 未登录用户由中间件自动发放**签名游客会话**，全部玩法零门槛可用——登录是升级项，不是门槛。

### 3.4 工程可靠性

- 全链路降级：AI 不可用 → 静态兜底剧场；热榜失败 → 本地话题池；未登录 → 游客会话；单图加载失败 → 渐变占位。
- 分享海报为纯前端 Canvas 绘制（名场面卡 / 法庭判决书两种），Web Share API 分享、剪贴板兜底。
- 提供站内 MCP 端点（`/api/mcp`），为 Agent 生态预留工具协议入口。

## 四、适配知乎社区的场景价值（重点）

**1. 为盐选故事资产创造"第二消费场景"。**
盐选故事是知乎最独特的内容 IP 库。入局让每一部作品从"一次性阅读"变成"可反复入局的互动体验"——读过的想回来玩个不同结局，没读过的玩完想去读原文，**为内容生态互相导流**。

**2. 把知乎的社区文化装进游戏机制。**
- 观点对抗 → **红蓝法庭**：知乎用户最爱"站队讲理"，法庭给这场站队一个有戏剧感、有结果、可分享的容器；
- 续写接力 → **二创工坊**：盖楼不再歪楼，每楼都是链上可溯的一格；
- 热榜议题 → **盐灵剧场**：每天用热榜出题、全场共答，议题变成 playable 的内容。

**3. 分享回流，闭环长在知乎里。**
对局结束一键生成**名场面分享卡 / 法庭判决书海报**，发回知乎想法与评论区——"我在《不提分就出不去的房间》里和李迟游对了一局戏"——新读者循着卡片点进来，又成为一个入局者。内容生长的循环，锚点始终在知乎社区。

**4. 官方能力，合规生长。**
全部社区数据（热榜、登录、用户资料）来自知乎开放平台官方接口，密钥仅存服务端，调用侧做了缓存与额度保护——作品的生命周期不依赖任何灰色手段。

## 六、下一步规划

1. **盐选故事 API 动态接入**：从官方故事接口拉取作品，让书架从 29 部长成一片森林
2. **知乎直答 NPC**：角色对话后台接直答/搜索 API，NPC 以角色口吻引用真实高赞回答——"故事里的引用都是真的"
3. **判决书回流想法**：法庭判决一键生成知乎想法草稿，闭环从"分享卡片"升级为"原生内容回流"
